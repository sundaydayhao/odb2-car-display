# OBDNode-C3：ESP-IDF 5.5 固件

这是独立的 OBD 采集节点工程。不要在副屏主工程中执行 `set-target esp32c3`。本工程已在 **ESP-IDF v5.5.5** 构建，通过主机协议与低功耗策略测试；尚未在新设计的实体板上运行。

## 构建与烧录

激活 ESP-IDF 5.5 环境，在本目录运行：

```powershell
./build.ps1 build
./build.ps1 -Port COMx flash
./build.ps1 -Port COMx monitor
```

也可传入 `-IdfPath` 或 `-IdfProfile`。主控固定 `esp32c3`、4 MB Flash、DIO 40 MHz。地址来自当前构建的 `build/flash_args`，不要使用副屏的烧录文件。固件镜像为 `build/obd_ble_node.bin`；本次没有向现有副屏或 ELM327 烧录。

首次使用板上 Flash 记录区，需要接 USB 数据测试点，在 USB 终端执行一次 `ATLOGFMT`。此命令会清空采集分区，固件不会因为挂载失败而自动格式化、也不会自动擦除 NVS。USB pogo 点没有 VBUS 输入：台架单独提供受控电源，不要把 USB 5 V 接到 3V3。

## BLE 与协议

广播名 `OBDNode-C3`，一个连接。服务 FFF0，FFF1 为通知／读取，FFF2 为写入／无应答写入；先订阅 FFF1，再发送以 CR 结尾的 ASCII 命令，每次等 `>` 后发送下一条。通知按实际 ATT MTU 分片，断连后丢弃旧会话的输入输出。

`ATI` 标识为 `OBDNode ELM327-compatible 0.1.0`，表示兼容接口，不冒充原厂 ELM 芯片。现有副屏的生产解析器已用于主机测试，可解析节点生成的双 ECU 转速响应；手机 BLE 实机互通仍待新板。

| 命令 | 行为 |
|---|---|
| ATZ / ATWS / ATD | 重置协议状态；回到被动监听 |
| ATI / AT@1 | 本设备版本／描述 |
| ATE0/1、ATH0/1、ATS0/1、ATD0/1 | 回显、帧头、空格、DLC 显示 |
| ATL0、ATCAF0/1 | CR 换行、OBD 自动格式；CAF0 不开放任意 CAN 发送 |
| ATCFC1、ATAT0/1/2 | 接受已有客户端初始化；本版只处理单帧 Mode 01，使用固定超时 |
| ATSTxx | 超时：十六进制值 × 4 ms，00 为 200 ms |
| ATSP6/7/8/9 | 明确选择 11/29 位、500/250 kbit/s |
| ATSP0 | 在当前速率下尝试 11 位再 29 位寻址，初始速率 500 kbit/s；不跨速率盲发探测 |
| ATDPN / ATDP | 当前协议编号／寻址格式 |
| ATSHxxx / ATSHxxxxxxxx | 仅允许 OBD 请求 ID 范围 |
| ATCRAxxx / ATCRAxxxxxxxx / ATCRA | 设置或清除接收 ID 过滤 |
| 01xx | 仅读取一个 Mode 01 PID，禁止清码、编码、任意原始帧发送 |
| ATRV | 校准 ADC 测得的保护后电压，未补偿反接二极管压降 |
| ATMA | 被动输出经典 CAN 原始帧；发送任意字符停止并返回 STOPPED |
| ATPC | 关闭 CAN，后续有效读取／监听命令可重新打开 |
| ATSTAT | RX、TX 请求、失败、bus-off、硬件丢帧、切换丢帧和队列计数 |
| ATLOG1 / ATLOG0 | 开始／结束板上 JSONL 记录；单次最多 60 秒或 1 MiB |
| ATLOGDUMP / ATLOGFMT | 仅 USB：导出／格式化记录区；执行时 CAN 关闭 |

本版不是完整 ELM327 实现。不支持 ISO-TP 多帧组装、VIN、DTC 清除、任意 UDS、CAN FD、K-Line 或 J1850。NO DATA 不能被解释为其他 CAN 帧已经解码。

## 默认低功耗策略

- **60 秒无主机数据请求就深睡眠**；仅保持 BLE 连接、或接收到车辆后台 CAN 报文，都不延后超时。
- 保护后电压持续 **30 秒 ≤ 12.0 V**，或 ADC 持续不可用，停止采集并休眠；即使客户端仍在请求也生效。
- 低电压休眠后，下一次启动先测电压。未达到阈值 + 0.3 V 时不启动 BLE，继续定时休眠。
- CAN 收发器保持 standby，TX_INHIBIT 保持高、状态灯关闭；GPIO3 可被收发器 RXD 的远程唤醒信号唤醒。
- CAN 唤醒后提供 15 秒连接机会；连续 3 次无人使用的唤醒后关闭 CAN 唤醒，防止后台报文造成耗电循环。
- 默认每 900 秒定时醒来，提供约 3 秒 BLE 窗口。定时器本身不清除误唤醒限制；收到主机请求，或检测到保护后电压 ≥ 13.2 V 时解除限制。电压只作为充电线索，不等于确认点火状态。
- USB 枚举连接用于台架调试时，自动休眠暂时旁路；显式 `ATSLEEP` 仍可测试睡眠。单次 Flash 记录不会无限延长唤醒时间。

深睡眠时 BLE 不在线。首次通常由车辆 CAN 活动唤醒；进入误唤醒退避后，连接可能需要等到定时窗口。这个取舍需要用实车休眠／唤醒行为继续验证。

| 设置命令 | 参数／默认值 |
|---|---|
| ATPOWER? | 查询当前策略和 USB 旁路状态 |
| ATIDLE60 | 无请求超时，30–600 秒 |
| ATWAKE900 | 定时唤醒间隔，60–3600 秒 |
| ATVLOW12000 | 保护后电压阈值，11000–12500 mV |
| ATSLEEP | 请求进入深睡眠 |

更改持久设置仅允许 USB 台架端执行，保存到 NVS；BLE 可查询但不能降低电压保护阈值。没有永久关闭省电的量产默认选项。`VIN_PROT` 与电池端存在保险丝／二极管压降，量产前必须用万用表校准，不能把 12.0 V 阈值直接宣称为准确电池端阈值。

长期停车平均电流的工程目标暂定 **≤ 0.5 mA（电池端，包括定时唤醒）**，不是已测结果。0.5 mA 连续 30 天约为 0.36 Ah；仍需同时考虑车辆本身静态电流、电池老化、温度和停车时长。测试应覆盖静默总线、周期后台报文、低电压、保持蓝牙连接但不请求、连续请求、Flash 记录、重复 bus-off 和唤醒风暴。

## 记录与丢包

手机可以继续通过 ATMA 保存原始文本。板上 `ATLOG1` 会创建 `/capture/latest.jsonl`，显式开始新记录会覆盖上次记录。记录包含序号、软件接收时刻 `t_us`、方向、ID、扩展标志、RTR、DLC 和数据；`tx_request` 表示已提交一次发送尝试，不表示 ECU 已收到。

SPIFFS、BLE 和 CAN 队列都有限；本版不承诺全总线无损采集。`ATSTAT` 分别给出硬件队列丢帧、驱动模式切换丢帧、BLE 和记录队列丢帧。JSONL 起始记录明确写入 `bus_loss_unknown:true`。时间戳不等于总线硬件到达时刻，捕获失败或达到容量上限会停止记录并保留失败状态。

## 测试和限制

```powershell
./test.ps1 -Cc <gcc路径>
```

主机测试直接编译本工程的协议／电源策略 C 代码及副屏已有的 `elm327_protocol.c`，覆盖分片输入、双 ECU 响应、非法写服务、错误 PID／帧长度、明确速率选择、监视中断、缓冲失败、断连复位和低功耗边界。

BLE 当前未强制加密／绑定。只读指令白名单和物理 TX 门控不等于完整访问控制；量产需要补充配对授权、签名升级和生产身份。新板尚未制造，未完成 CAN 电气、BLE 射频、GPIO 保持、实车低功耗和抗扰测试。

硬件引脚以 `main/board_pins.h` 和 `../../hardware/obd-ble-node/design.json` 为共同依据。
