# P4 汽车副屏

ESP32-P4 Function EV Board **v1.4**，原配 **7 寸 1024×600 触屏与 MIPI 摄像头**，ESP-IDF **5.5.x**、LVGL 9.2。
车辆仪表、影音中心（SD 音乐、FM 电台预留页、小智语音控制、可选摄像头）、SD 诊断记录、Wi-Fi STA（路由器或手机热点）、HTTPS 上传与签名 OTA。
已移除微雪 S3 的屏幕/触摸实现，仅保留 **ELM327 BLE** 车辆数据入口，不恢复有线总线采集，也不创建 `projects`。

完整接线、C6 配套固件、配网、语音绑定、日志回放和本地服务器使用见 **[P4 上板与联调](docs/P4_BRINGUP.md)**。
尚无云服务器时，默认不上传、不自动升级；摄像头功能默认不编入，启用配置后还需本地操作开启；麦克风开机后在本机识别唤醒词，唤醒后才向小智上传本轮语音。

## 语音唤醒与连续对话

连接 Wi-Fi 并完成校时后，说 **“你好小智”**，等小智回应后直接说问题，无需触摸或按住按钮。
回复结束后可以直接追问，不用再次唤醒；一段时间没有说话，服务端结束会话后才回到待唤醒。“设置 → 语音助手”显示唤醒词、状态和首次绑定码；绑定完成后重新唤醒。
待机音频只在本机处理，不上传；真实唤醒后上传约两秒唤醒音频及对话，断句与空闲结束由服务端控制。模型打包进应用，保持原分区及签名 OTA/回滚流程。
麦克风监听与音乐输出可同时工作；检测到唤醒后，音乐暂停。回复时不接受新的唤醒，避免设备声音再次触发。
各版本的实际唤醒、连续对话、响应时间和已知问题见 [P4 联调说明](docs/P4_BRINGUP.md#8-验收顺序)。

## 使用

1. 将支持 BLE 的 ELM327 适配器接到车辆诊断口，车辆上电。
2. 断开手机诊断软件与适配器的连接，多数适配器只允许一个客户端。
3. 首次进入「设置 → 蓝牙设置 → 扫描设备」，点选自己的适配器连接。每次扫描十五秒，扫描不会自行连接。
4. 成功初始化的适配器会被保存；下次开机、重新开启蓝牙或意外断开时只尝试重连它一次，失败后停止，等待手动选择。手动断开、关闭或忘记不会立即连回。
5. 顶部蓝牙图标显示连接状态，详情在「设置 → 蓝牙设置」查看；缺失车辆数据为 `--`。

P4 通过板载 C6 提供 Bluetooth LE，不支持 Classic SPP；标注“蓝牙 ELM327”的适配器不一定是 BLE。
参见 [官方 v1.4 板卡说明](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32p4/esp32-p4-function-ev-board/user_guide_v1.4.html)。
适配器的蓝牙串口传输的是 ELM ASCII 指令/响应，本机不会把每个通知包误当成独立 CAN 帧。

## 已实现

- NimBLE Central 手动扫描、列表点选连接，最多显示十六个可连接设备；已保存设备只自动重连一次，失败不循环扫描或切换其他设备。
- 按完整地址和地址类型区分同名设备；自动发现服务、特征与真实 CCCD，支持 Notify/Indicate。
- FFF0、FFE0、Nordic UART 三类串口服务，以及自定义服务/特征 UUID。
- MTU 协商、写入应答/无应答、通知分片拼接、单指令串行事务、`>` 结束符和容量检查。
- 超时或溢出后关闭当前连接，隔离迟到响应；用连接代次防止旧连接数据进入新会话。
- ELM/STN 身份检查、AT 初始化、自动识别 ISO 15765-4 协议 6/7/8/9。
- 支持 PID 位图查询和单 ECU 固定；11 位/29 位响应头、填充字节、边界校验以及有界 ISO-TP 重组。
- 每项数值独立失效时间；断开连接立即清空实时有效标记，UI 不阻塞等待蓝牙。
- 可选 BLE 配对、明确配置的 SMP passkey、NVS 绑定保存。不自动覆盖冲突的旧绑定。
- 乐鑫 `esp_xiaozhi 0.1.2` + `esp-sr 2.4.6`，说“你好小智”唤醒，按官方 AUTO 流程由服务端断句并回复；回复后继续聆听，服务端结束后回待唤醒。已接入 AEC，声学效果待实板验证；不支持回复中语音打断。
- 影音中心提供 SD MP3 播放、FM 空白预留页和语音助手开关；摄像头默认关闭，配置启用后支持手动预览/拍照/相册，不录像、不上传画面。
- SD 原始事务记录与解析快照，有界容量、掉包标记和重启恢复；HTTPS 幂等上传。
- 本地 HTTPS 服务、固件签名发布、离线回放工具；P4 双 OTA 槽、手动驻车升级及启动自检回滚。

手机 App 的 CAN 监听单独运行，只记录适配器在诊断口可见的经典 CAN；手机采集前需在副屏蓝牙设置中关闭车辆连接（旧固件可关闭副屏），避免争用适配器。

## 配置

在 `idf.py -B display_board/build menuconfig` 的 **ELM327 BLE Dashboard** 中配置：

- 设备选择在副屏蓝牙扫描列表完成，旧名称/地址过滤配置不再参与连接；随机地址未绑定且发生轮换时，需要重新扫描选择。
- UUID：三项同时设置或全部留空，详见 [BLE 协议实现](docs/ELM327_BLE.md)。
- 配对：默认按服务的加密要求触发；写入特征需加密的适配器可打开预先配对。
- 指令间隔：默认 50 ms；普通响应 1500 ms；初次车辆搜索 20000 ms。

工程使用显示板自己的配置：默认值由 `display_board/sdkconfig.defaults` 和 `display_board/main/Kconfig.projbuild` 提供，
当前构建配置保存在 `display_board/sdkconfig` 中，依赖缓存保存在 `display_board/managed_components/`，包含 BLE、屏幕和 PSRAM 参数。

## 构建与烧录

显示板构建产物位于 `display_board/build`，已经切换为 P4 目标。使用本机 IDF 5.5.5 环境包装器：

```powershell
.\tools\idf55.ps1 build
# 核对 v1.4 的 USB-to-UART 口，把 COMx 替换为实际串口
.\tools\idf55.ps1 -IdfArgs @('-p', 'COMx', 'flash', 'monitor')
# 配套 C6 无线固件，产物在 display_board/build/c6，通过 C6 独立编程口烧录
.\tools\build_c6.ps1
```

按官方要求使用 USB/稳压电源，不要直接接车辆 12 V。
使用 16 MB Flash、两个 6 MB 应用槽；主应用起始地址 `0x20000`。
首次在 P4 上使用完整 `flash` 写入新的引导程序、分区表、otadata 和应用，不能套用旧 S3 的地址或只执行 `app-flash`。
NVS 不会在失败时自动擦除；没有卡时记录状态为不可用，SD 卡不会被自动格式化。
