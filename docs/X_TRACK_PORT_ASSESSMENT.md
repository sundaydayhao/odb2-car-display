# X-TRACK 移植评估

评估日期：2026-09-15。对象为 [FASTSHIFT/X-TRACK](https://github.com/FASTSHIFT/X-TRACK)，固定源码版本 `c42b8e5605e50838f4c0c9828385948fa33ab485`，该提交日期为 2025-11-08。本项目基线为本地 0.3.0 唤醒词固件构建。

## 结论

**可以移植，建议复用离线地图、坐标转换和轨迹处理模块，并接入当前 ESP-IDF / LVGL 9 工程。** 原工程围绕小屏自行车码表组织，整体搬入会重复引入界面管理、硬件抽象和数据中心，改造成本高于模块复用。

第一版适合提供：SD 卡离线地图、当前位置、触摸缩放与回到当前位置、行驶轨迹、GPX 导出，以及 GPS 速度和 OBD 车速的分别显示。

X-TRACK 官方功能包括离线地图、定位与轨迹记录；本次检查的页面、数据处理模块和官方功能清单没有完整的目的地搜索、道路路线规划、偏航重算或转向语音导航实现。因此，移植完成也不能直接等同于高德或百度式导航。[上游功能说明](https://github.com/FASTSHIFT/X-TRACK/tree/c42b8e5605e50838f4c0c9828385948fa33ab485)

## 平台差异与适配范围

| 项目 | X-TRACK | 当前汽车副屏 | 判断 |
| --- | --- | --- | --- |
| 主控与系统 | AT32F435、Arduino 风格 HAL | ESP32-P4、ESP-IDF 5.5.5 | 算法可复用，驱动必须替换 |
| 显示 | 240×240 SPI 屏、旋钮 | 1024×600 触摸屏 | 重新设计布局与操作 |
| 图形库 | 自带 LVGL 8.3.0-dev | LVGL 9.2.0 | 地图控件需实质适配 |
| 定位 | ATGM336H GNSS，TinyGPSPlus 串口解析 | 尚无 GNSS 驱动和定位数据通路 | 必须补充定位来源 |
| 存储 | SD 卡地图及轨迹文件 | 已有 SD 卡诊断记录、音乐 | 可共用介质，需统一挂载状态和访问调度 |
| 功能整合 | 自行车运动数据、独立页面管理 | OBD、小智语音、音乐、摄像头、OTA | 复用现有服务及 UI 入口 |

上游版本以实际头文件为准：[LVGL 版本](https://github.com/FASTSHIFT/X-TRACK/blob/c42b8e5605e50838f4c0c9828385948fa33ab485/Software/X-Track/Simulator/LVGL.Simulator/lvgl/lvgl.h)。本地依赖见 [显示板组件清单](../display_board/main/idf_component.yml)。

| 模块 | 可复用程度 | 需要做的工作 |
| --- | --- | --- |
| `MapConv` / `TileSystem` | 高 | 接入经纬度数据、地图目录和缩放边界；为现有 C 服务提供 C 接口 |
| `TrackPointFilter` / `TrackLineFilter` | 较高 | 适配坐标与采样规则，明确轨迹简化误差；显示简化不能直接替代原始记录 |
| `PointContainer` | 候选 | 核对最大轨迹长度、内存上限和长期运行行为后决定是否采用 |
| GPX 记录 | 格式与流程可借鉴 | 原 GPX 类依赖 WString，改为现有 stdio 流式写入；正确记录 UTC 和 WGS84 坐标 |
| `LiveMapModel` | 部分 | 将上游 DataCenter 订阅替换为当前工程数据快照和事件 |
| `LiveMapView`、`lv_poly_line`、`lv_img_png` | 低至中 | 适配 LVGL 9 绘制与图像接口，重做大屏触摸布局 |
| GNSS、屏幕、按键和电源 HAL | 低 | 使用当前 BSP / ESP-IDF 驱动，不引入 AT32 硬件层 |

界面迁移不只是 API 重命名：`LiveMapView` 直接访问 LVGL 8 的 `lv_img_t` 内部宽高，自定义 PNG 控件也依赖旧版绘制接口。优先使用 LVGL 9 图像描述符和有上限的瓦片缓存。[地图视图源码](https://github.com/FASTSHIFT/X-TRACK/blob/c42b8e5605e50838f4c0c9828385948fa33ab485/Software/X-Track/USER/App/Pages/LiveMap/LiveMapView.cpp)

## 主要约束

### 1. 定位数据来源

推荐独立使用时增加 UART GNSS 模块，由 ESP-IDF UART 驱动解析定位语句。具体引脚、接口电平、电源和天线安装应按最终硬件版本核对；本评估不指定未验证的 GPIO。

也可以由手机提供定位，但当前 Android App 只有 BLE OBD 采集能力，需要增加定位权限、定位服务及向 P4 传输数据的协议。手机热点只提供网络连接，不会自动向副屏传递经纬度。现有单板硬件方案未列入 GNSS，不能把手机或车端定位当作现成输入。

定位服务应包含有效性、精度或质量、时间戳和失效状态；断开、无定位或过期数据必须明确显示。上游地图模型有无定位时使用默认坐标的逻辑，移植时应区分地图初始中心与有效的车辆位置。

### 2. 固件空间已经偏紧

当前已构建的 0.3.0 应用为 **5,731,648 字节**；每个 OTA 应用分区为 **6,291,456 字节（6 MiB）**，剩余 **559,808 字节，约 547 KiB / 8.9%**。见 [构建验证记录](../build/wake-validation.json) 和 [分区表](../partitions.csv)。

这不是已经测得的 X-TRACK 移植后大小。坐标和轨迹核心较轻，但新页面、字体、图像解码器和 C++ 依赖会继续增加镜像体积，必须逐阶段构建测量。

地图和大体积图像放 SD 卡；优先共用当前 LVGL、字体和服务。保留小智模型及双 OTA 能力。若精简后仍放不下，再单独评估分区调整和现有设备的升级路径，不能直接把修改分区表视为普通应用 OTA。

### 3. 大屏地图的内存和实时性

当前目标配置为 360 MHz ESP32-P4、32 MiB PSRAM，具有实现基础；并发后的可用堆和耗时仍需上板测量。

以下是预算示例，不是运行测量：256×256 的 RGB565 瓦片为 128 KiB；1024×600 全屏在四边各预留一块瓦片时，缓存约 `(4+2)×(3+2)=30` 块，占 3.75 MiB。若采用 32 位像素则为 7.5 MiB，另需解码临时区和对象开销。可以按实际地图区域缩小缓存，不能无上限加载。

瓦片读盘和解码放后台任务，结果通过现有 UI 锁更新；避免在 LVGL 回调中批量读取 SD 卡。需同时验证唤醒词持续监听、对话音频、音乐或摄像头预览下的帧率、音频欠载、堆水位及看门狗。

### 4. 地图文件与 SD 卡服务

上游地图路径为 `/MAP/{z}/{x}/{y}.bin`，还支持自定义 PNG 控件。LVGL 8 的二进制图像不能假定与 LVGL 9 格式兼容。第一版可采用离线转换的 RGB565 数据和明确的自定义文件头，或使用适配后的 LVGL 9 图像文件；地图准备工具必须与固件格式一致。[瓦片路径代码](https://github.com/FASTSHIFT/X-TRACK/blob/c42b8e5605e50838f4c0c9828385948fa33ab485/Software/X-Track/USER/App/Utils/MapConv/MapConv.cpp)

当前 LVGL 原生文件系统适配及 PNG 解码均未启用。SD 卡挂载目前位于 [诊断记录任务](../display_board/main/recorder.c)，应先提取公共存储初始化和就绪状态，再接入地图与 GPX。处理缺卡、缺瓦片、读盘错误和记录空间不足，避免地图故障影响现有功能。

地图坐标系必须与瓦片源匹配。上游提供坐标偏移转换，但不能对所有地图和所有地点无条件启用；原始定位记录与 GPX 保留 WGS84，显示坐标转换单独处理。

## 建议接入结构与实施顺序

```text
UART GNSS / 手机定位 → gps_service → 定位快照 → 地图页面
                                      └──→ 轨迹记录 → SD / GPX
SD 地图文件 → 后台瓦片读取 → 有上限的 PSRAM 缓存 → 地图页面
OBD 数据服务 ───────────────────────────────→ 同屏车辆数据
```

1. **地图原型**：先用回放坐标驱动 LVGL 9 地图页面，完成 SD 瓦片读取、拖动缩放、缺图提示，并测量镜像增量及内存。此阶段不依赖新增 GNSS 硬件。
2. **定位接入**：实现统一定位接口，再接入 UART GNSS 或手机；验证无定位、失效、恢复及显示坐标系。
3. **轨迹与行程**：保存时间、原始位置及必要车况，提供 GPX 导出，验证跨文件、断电和存储错误处理。
4. **并发与实车验证**：地图移动和缩放时保持语音唤醒可用；验证音频、OBD 刷新和摄像头使用场景，记录资源峰值，确认仍能进行双分区 OTA。

按当前架构判断，核心算法复用工作量较小；LVGL 9 地图页面、SD 缓存与定位服务属于中等改造；达到长期稳定的车载使用状态还需要并发和实车验证。完整路线导航应作为另一个需求评估，不能计入这次模块移植的现成功能。

## 已完成的验证与边界

- 固定上游提交并检查地图、定位、轨迹、存储、HAL 和图形控件源码。
- 在 `build/xtrack-review/` 使用 Cygwin GCC / G++ 主机编译，未修改上游的 `MapConv`、`TileSystem`、`GPS_Transform`、`TrackPointFilter` 源文件。
- 基础断言通过：经纬度原点投影、瓦片及文件路径、缩放坐标转换、缩放上下限、经纬度投影往返、100 个直线轨迹点压缩后保留首尾。见 [测试源码](../build/xtrack-review/smoke.cpp) 和 [测试输出](../build/xtrack-review/smoke.log)。
- 该结果证明所测核心模块可脱离原硬件和 LVGL 编译运行；不代表完整界面已经适配，也不代表 ESP32 固件构建、地图性能或实车功能已经验证。
- 本次仅新增评估文档和忽略目录中的评估材料，没有把 X-TRACK 接入生产固件，也没有烧录设备。此前唤醒词固件的实机验证仍待进行。
