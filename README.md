# P4 汽车副屏

ESP32-P4 Function EV Board **v1.4**，原配 **7 寸 1024×600 触屏与 MIPI 摄像头**，ESP-IDF **5.5.x**、LVGL 9.2。
车辆精致仪表、小智手动语音对话、本地摄像头预览、SD 诊断记录、手机热点 STA、HTTPS 上传与签名 OTA。
已移除微雪 S3 的屏幕/触摸实现，仅保留 **ELM327 BLE** 车辆数据入口，不恢复有线总线采集，也不创建 `projects`。

完整接线、C6 配套固件、配网、语音绑定、日志回放和本地服务器使用见 **[P4 上板与联调](docs/P4_BRINGUP.md)**。
尚无云服务器时，默认不上传、不自动升级；摄像头和语音采集需本地操作开启。

## 使用

1. 将支持 BLE 的 ELM327 适配器接到车辆诊断口，车辆上电。
2. 断开手机诊断软件与适配器的连接，多数适配器只允许一个客户端。
3. 开发板上电后自动扫描、连接、订阅串口服务、初始化适配器并轮询车辆参数。
4. 页面显示「搜索设备 → 连接设备 → 同步设备 → 等待车辆/实时车况」。缺失数据为 `--`。

P4 通过板载 C6 提供 Bluetooth LE，不支持 Classic SPP；标注“蓝牙 ELM327”的适配器不一定是 BLE。
参见 [官方 v1.4 板卡说明](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32p4/esp32-p4-function-ev-board/user_guide_v1.4.html)。
适配器的蓝牙串口传输的是 ELM ASCII 指令/响应，本机不会把每个通知包误当成独立 CAN 帧。

## 已实现

- NimBLE Central 主动扫描和自动重连；连接/发现看门狗；失败设备短暂退避。
- 按名称或指定地址筛选设备；自动发现服务、特征与真实 CCCD，支持 Notify/Indicate。
- FFF0、FFE0、Nordic UART 三类串口服务，以及自定义服务/特征 UUID。
- MTU 协商、写入应答/无应答、通知分片拼接、单指令串行事务、`>` 结束符和容量检查。
- 超时或溢出后关闭当前连接，隔离迟到响应；用连接代次防止旧连接数据进入新会话。
- ELM/STN 身份检查、AT 初始化、自动识别 ISO 15765-4 协议 6/7/8/9。
- 支持 PID 位图查询和单 ECU 固定；11 位/29 位响应头、填充字节、边界校验以及有界 ISO-TP 重组。
- 每项数值独立失效时间；断开连接立即清空实时有效标记，UI 不阻塞等待蓝牙。
- 可选 BLE 配对、明确配置的 SMP passkey、NVS 绑定保存。不自动覆盖冲突的旧绑定。
- 乐鑫 `esp_xiaozhi 0.1.2`，ES8311 + Opus 录音/播放，手动按住对话；尚无唤醒词/AEC/全双工。
- 摄像头手动启停，本地有界预览，不录像、不上传画面、不宣称疲劳预警。
- SD 原始事务记录与解析快照，有界容量、掉包标记和重启恢复；HTTPS 幂等上传。
- 本地 HTTPS 服务、固件签名发布、离线回放工具；P4 双 OTA 槽、手动驻车升级及启动自检回滚。

| 数据 | 标准 PID | 单位 |
| --- | --- | --- |
| 车速 | 01 0D | km/h |
| 发动机转速 | 01 0C | rpm |
| 发动机负载 | 01 04 | % |
| 节气门开度 | 01 11 | % |
| 冷却液温度 | 01 05 | °C |
| 油量 | 01 2F | % |
| 控制模块电压 | 01 42 | V |

只轮询所选 ECU 声明支持的参数。增压相对压力不使用固定大气压猜测；档位、胎压、
变速箱温度、续航、油耗等尚未接入的参数保持不可用。此版本不执行清码、刷写、控制执行器或全总线监听。

## 配置

在 `idf.py -B build menuconfig` 的 **ELM327 BLE Dashboard** 中配置：

- 名称：默认留空，匹配包含 OBD、ELM、VLINK、V-LINK、VEEPEAK、VGATE 的名称，忽略大小写。
- 地址：可指定 `AA:BB:CC:DD:EE:FF`，优先于名称筛选。隐私地址可能轮换。
- UUID：三项同时设置或全部留空，详见 [BLE 协议实现](docs/ELM327_BLE.md)。
- 配对：默认按服务的加密要求触发；写入特征需加密的适配器可打开预先配对。
- 指令间隔：默认 50 ms；普通响应 1500 ms；初次车辆搜索 20000 ms。

工程使用统一配置：默认值由根 `sdkconfig.defaults` 和 `main/Kconfig.projbuild` 提供，
当前构建配置保存在根 `sdkconfig` 中，包含 BLE、屏幕和 PSRAM 参数，无需额外的项目预设。

## 构建与烧录

继续使用原来的 `build` 目录，已经切换为 P4 目标。使用本机 IDF 5.5.5 环境包装器：

```powershell
.\tools\idf55.ps1 build
# 核对 v1.4 的 USB-to-UART 口，把 COMx 替换为实际串口
.\tools\idf55.ps1 -IdfArgs @('-p', 'COMx', 'flash', 'monitor')
# 配套 C6 无线固件，产物在 build/c6，通过 C6 独立编程口烧录
.\tools\build_c6.ps1
```

按官方要求使用 USB/稳压电源，不要直接接车辆 12 V。
使用 16 MB Flash、两个 6 MB 应用槽；主应用起始地址 `0x20000`。
首次在 P4 上使用完整 `flash` 写入新的引导程序、分区表、otadata 和应用，不能套用旧 S3 的地址或只执行 `app-flash`。
NVS 不会在失败时自动擦除；没有卡时记录状态为不可用，SD 卡不会被自动格式化。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `main/elm327_ble.c` | NimBLE 连接、服务订阅、串行传输和重连 |
| `main/elm327_protocol.c` | 有界 ASCII/ISO-TP 响应解析，不依赖硬件 |
| `main/obd2.c` | AT 会话、能力发现、参数调度与快照发布 |
| `main/obd2_decode.c` | 数值换算和逐字段过期策略，不依赖硬件 |
| `main/ui.c` | 官方 BSP 屏幕/触摸、线程锁及显示模型映射 |
| `main/dashboard.c` | 五页彩色界面、主题、手动导航、显式演示模式 |
| `main/service_panel.c` | 独立 LVGL 设备中心、语音/摄像头/上传/更新交互 |
| `main/voice_service.c`、`main/camera_service.c` | 小智音频链路与本地摄像头预览 |
| `main/recorder.c`、`main/cloud_service.c` | SD 记录、HTTPS 上传、签名 OTA |
| `main/device_services.c`、`main/network_service.c`、`main/device_console.c` | NVS 设置、热点 STA 与串口配置 |
| `tools/lab_server.py`、`tools/replay_recording.py` | 本地诊断服务、升级发布与原始记录回放 |
