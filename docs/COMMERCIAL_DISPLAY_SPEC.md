# 汽车副屏产品定义与界面规格

版本：2026-09-06，设计阶段。目标是老式燃油车的 7 寸增补仪表，不替换原车法定仪表。
本稿先定义用户需要的信息和界面，随后才做车型能力调查、数据采集与硬件选型。
文中的优先级是本项目的产品取舍，不代表行业统一标准。原型全部使用示例数据。

## 产品定位

核心用户是希望补齐原车信息、减少车辆异常带来的不确定性，同时让车内更现代的普通车主。
基本版解决日常驾驶、关键车况和行程成本；增强版增加四轮胎压；性能包面向有明确需求的车主。
专业调校信息不应占据普通用户的首页。导航、音乐、摄像头和语音助手是后续可选扩展，
不应挤掉副屏最重要的驾驶数字和异常提醒。

参考商用品的实际功能：

- [ScanGauge III](https://www.scangauge.com/products/productsscangauge-iii/) 提供可选仪表、油耗、自动行程统计、故障读取、车型扩展参数和可配置告警。本产品借鉴其“实时监控 + 行程 + 诊断”的分工。
- [Banks iDash](https://official.bankspower.com/owners_manual/97654-idash-1-8-datamonster-and-super-gauge/) 提供参数选择、告警和记录；[记录文档](https://official.bankspower.com/owners_manual/97654-idash-1-8-datamonster-and-super-gauge/97654-idash-1-8-datamonster-and-super-gauge-section-6-data-logging/) 明确指出记录参数越多可能降低记录速率。本项目因此区分快速驾驶数据与慢速状态数据。
- [AiM MX TFT](https://aim-sportline.com/en/products/mx-tft-series/index.htm) 支持告警、换挡灯及扩展传感器。本项目借鉴告警优先和多数据来源，不把可读取的所有字段同时摆上首页。
- [Racelogic Performance Box](https://racelogic.support/motorsport/discontinued-legacy/performance-meters/performance-box-touch-v1/ug/04-display-modes/) 将加速、制动和定位计时作为独立性能用途。本项目把性能测量单列，不与日常行车混为一体。

## 信息架构

| 页面 | 用户关心的问题 | 默认内容 |
| --- | --- | --- |
| 驾驶 | 现在开得怎样，还能开多远？ | 车速、转速、档位（如支持）、剩余油量、预估续航、瞬时油耗；底部四个自选数据位 |
| 车况 | 有哪些原车没告诉我的状态？ | 水温、机油温度、变速箱温度、进气温度、机油压力、系统电压；故障与保养入口 |
| 胎压 | 哪个轮胎需要关注？ | 四轮位置、压力、温度、更新时间、低压/高温/漏气/失联状态 |
| 行程 | 这次开了多少、花了多少？ | 距离、用时、平均速度、平均油耗、耗油量、燃油成本、怠速时间、油耗趋势 |
| 性能 | 动力和驾驶反馈如何？ | 转速、增压、节气门、负载、横纵向加速度；历史加速/制动成绩 |

日间与夜间是全局外观，不再各占一个功能页面。五页只通过用户操作切换，
告警在固定区域出现，不自动翻页抢走当前内容。触屏用底部导航；非触屏用旋钮和确认/返回键。
保养、单位、车辆档案、阈值和首页数据位放在设置/二级页面。

年轻车主与改装车方向提供三套彩色外观：夜行霓虹（青绿/荧光黄/玫红）、
熔岩赛道（橙红/冰蓝/暖黄）、酸性机能（荧光黄/薄荷绿/玫红）。
外观与功能页面独立，可手动换肤；夜间以中性深色底保留对比，日间采用更深的彩色前景。
分段转速带、倾斜数字与切角档位标识强化运动感，不增加闪烁装饰或自动页面轮播。
红色异常必须同时有文字或部位标识，不能仅靠主题颜色传达车辆状态。

## 参数清单

P0 为基础版优先交付；P1 为车型支持或选装后提供；P2 为专业扩展。
“优先交付”不等于所有车辆均能获取。不支持时隐藏可选项或明确显示不可用。

| 参数组 | 参数与单位 | 级别 | 设计要求与来源边界 |
| --- | --- | --- | --- |
| 行驶 | 车速 km/h、发动机转速 rpm | P0 | 首页最高优先级；速度与转速来源独立，不能因一个缺失把另一个置零 |
| 档位 | P/R/N/D、实际档位 | P1 | 没有可靠来源就隐藏；根据转速车速估算时必须标注“估算” |
| 油量 | 剩余油量 %、剩余燃油 L | P0/P1 | 升数需要油箱档案/标定，不将不准确的油位线性映射成精确升数 |
| 续航 | 预估剩余里程 km | P0 | 显示“预估续航”；需要有效油量和近期油耗，不把历史缓存当实时续航 |
| 油耗 | 瞬时/平均 L/100km，怠速 L/h | P0 | 停车时切换 L/h，避免除以零；估算或未标定须标识 |
| 燃油开销 | 耗油量 L、燃油成本 元、每公里成本 元/km | P0 | 油价由用户输入；成本为燃油估算，不冒充总用车成本 |
| 基础车况 | 冷却液温度 °C、系统电压 V | P0 | 温度和电压提示按车辆档案与发动机状态解释，不做虚假的健康分数 |
| 热管理 | 机油温度、变速箱温度、进气温度 °C | P1 | 显示本次峰值；“机油”和“变速箱”必须明确区分 |
| 润滑 | 机油压力 bar/kPa | P1 | 不将“机油压力开关正常”伪造成压力数值；告警结合发动机运转状态 |
| 进气 | 增压压力 bar、歧管绝对压力 kPa | P1 | 相对增压与绝对压力分开；自吸车不强行显示涡轮增压 |
| 动力需求 | 发动机负载 %、节气门开度 %、加速踏板 % | P0/P1 | 三者语义不同；原型显示前两项，踏板进入可选数据位 |
| 胎压 | 四轮压力 bar/kPa/psi、温度 °C | P1，增强版核心 | 车轮位置明确；可能需要独立胎压接收器或车型扩展数据 |
| 胎压状态 | 低压、高温、快速漏气、传感器失联/低电量 | P1 | 阈值和冷胎基准来自用户/车辆档案；失联不能显示“正常” |
| 行程 | 本次/今日/本箱油的距离、时长、平均/最高速度、怠速时间 | P0 | 起止事件、短暂停车合并、跨日和断电保存应定义一致 |
| 故障 | 发动机故障灯状态、当前/待定/历史故障、冻结帧、就绪状态 | P0/P1 | “未检测到故障”不同于“未读取”；中文描述不冒充维修结论 |
| 保养 | 机油/机滤/空滤/冷却液/变速箱油的日期和里程提醒 | P1 | 原车总里程若不可读，使用手动基准加累计距离，必须标识 |
| 记录 | 关键参数趋势、峰值、告警事件、故障时刻快照 | P0/P1 | 默认保存有限窗口，明确时间戳与数据质量；支持后续手机导出 |
| 环境 | 室外温度 °C、时间、海拔 m、坡度 % | P1 | 时钟、温度、定位和惯性数据可能来自不同硬件 |
| 底盘/车身 | 转向灯、车门、驻车制动、巡航、灯光 | P2 | 强车型依赖；未知时不绘制“关闭”或“未拉手刹”等确定状态 |
| 专业发动机 | 空燃比/λ、燃油修正、点火提前角、燃油压力、排气温度 | P2 | 专业页和自选字段提供，明确单位及适用车型，不进普通首页 |
| 柴油专用 | 颗粒捕集器负载/压差/再生状态、尿素余量 | P2 | 按动力类型提供车型包，汽油车隐藏 |
| 性能测量 | 0–100 km/h、80–120 km/h、100–0 制动距离、横/纵向 g | P1/P2 | 独立定位/惯性能力评估；没有精度依据不展示毫秒级“专业成绩” |
| 圈速/记录 | 单圈、分段、最佳圈、轨迹 | P2 | 需要定位、赛道定义与可验证的计时方案，不靠普通低速轮询承诺精度 |

不默认显示马力和扭矩：没有标定模型和输入质量保证时，数字很容易显得专业却不可信。
“机油寿命”“续航”“油耗”“里程”如为推算，都保留来源与校准状态。

## 首页默认组合

大号车速为唯一视觉中心，转速为横向细刻度。旁侧提供档位、预估续航、剩余油量和瞬时油耗。
底部默认水温、机油温度、系统电压、平均油耗，可由用户在停车后替换为胎压、变速箱温度等。
保持 6–8 项主要信息的阅读负担；档位、时间、告警属于辅助状态，不再堆满多个大圆盘。
车况页承接更详细的数据，首页不显示协议、芯片、串口或开发板名称。

## 必须设计的状态

| 状态 | 展示与行为 |
| --- | --- |
| 未连接 | 实时数字为 `--`，状态为“等待车辆”；历史行程标注历史身份 |
| 车辆不支持 | 可选首页数据位替换；详情页明确“车辆暂不支持” |
| 传感器未配置 | 显示“未配置”，提供设备入口；不画空白的正常胎压 |
| 有效实时数据 | 稳定数字布局、真实单位和时间戳 |
| 估算/未标定 | 数值旁保留“预估”/“估算”标记；极低置信度不显示精确数值 |
| 数据过期 | 清空实时值或标“数据已过期”；缓慢更新的胎压不能使用与车速相同的过期时间 |
| 提醒 | 琥珀色加文字，持续条件满足后提示，恢复后自动撤回 |
| 紧急异常 | 红色加明确事件、目标部位和当前数值；可暂静音但视觉提示保留 |
| 冷车/怠速/熄火 | 对应温度、油耗和电压语义切换；不把冷车温度低或熄火电压较低一概判故障 |

告警至少包含延时、滞回、优先级、静音时限和事件记录。阈值按车型设置，
不把某个演示数值写死为所有车辆的标准。例：机油压力判断需要区分发动机是否运转。

## 数据模型先行，采集实现后置

显示项统一包含：键名、数值、单位、采样时间、有效性、来源、估算标记、置信度、告警状态。
来源可以是车辆标准数据、车型扩展、独立传感器、定位/惯性模块或计算结果。
UI 只消费该模型，不直接发请求或根据协议报文画控件。

后续目标刷新率可先分档：车速/转速 5–10 Hz，动力/压力 2–10 Hz，
常规温度/电压 1–2 Hz，胎压跟随传感器真实周期，行程统计 1 Hz。
这些是体验目标，必须在实际总线、转接设备和 MCU 上测量后调整；
画面刷新与采样独立，不通过动画伪造测量精度。

## 首版交付范围

1. 先评审本稿五页原型、默认参数与缺失/告警状态。
2. 再按目标车型验证参数可得性，确定基础版与增强版配置。
3. 建立显示模型、示例数据源和真实数据源，迁移到独立 LVGL 页面。
4. 最后接入解析、胎压/定位等硬件和存储，再实车验证刷新、休眠、唤醒和提示行为。

当前原型不代表硬件已支持这些参数，本轮不烧录示例数据固件。
