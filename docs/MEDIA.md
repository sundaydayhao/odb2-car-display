# 联网多媒体（0.2.6）

在底部选择「多媒体」，可切换「在线音乐」与「网络电台」。音源列表与播放器分栏显示，共用原有六种外观。
连接 Wi-Fi 热点后点选音源开始播放；支持播放/暂停、上一首/下一首（电台为换台）、停止、音量与已播放时间。
开机不自动播放。音量和两个自定义地址保存到独立的 `media` NVS 命名空间。

「设置 → 多媒体」管理音乐与电台地址。当前接受 HTTP/HTTPS **MP3 音频直链**与 MP3 直播流；
网页链接、登录服务、HLS/M3U/PLS 播放清单、AAC/OGG/DRM 音源不在本版支持范围内。
网络电台通过热点收听；本板工程没有调频接收器驱动，因此没有离线 FM 频率调谐、搜台或天线信号读数。

音源只在点击播放后联网获取，不打包歌曲。电台地址与网络可用性可能变化，自定义地址可用来替换失效音源。
2026-09-11 桌面端直接联网检查四个默认地址，均返回 HTTP 200、`audio/mpeg`；音乐具有 ID3 头，直播从 MP3 流中途接入。
此项仅证明桌面网络可访问，不代替板端播放或听音检查。

## 播放链路与资源

`HTTP/HTTPS → 去除 ICY 元数据 → 192 KiB PSRAM 字节缓冲 → MP3 帧/ID3 解析 → esp_audio_codec 2.3.0 → 单声道 PCM → ES8311/I2S`。
使用现有 IDF 5.5.5、BSP 5.2.2 与 MP3 解码库，没有升级依赖。
立体声音频按两个有符号声道的平均值转为单声道；接受 8–48 kHz、16 位输出。
输入帧缓冲 4 KiB，PCM 输出缓冲 4608 字节，均在 PSRAM；数据不会无限累积或落盘。

下载任务独占 HTTP 客户端，播放器任务独占 MP3 解码器。停止/换台通过代次号取消旧请求，
等待下载任务退出后才清空共享缓冲；旧连接不能把音频混入新音源。HTTP 操作设有超时。
对重定向检查协议与长度，HTTPS 使用系统证书包验证，不接受跳过证书验证的配置。
直播分批送达时，2 秒读取超时（`ESP_ERR_HTTP_EAGAIN`）只用于检查取消请求；连续约 10 秒没有数据才判为读失败。
保留连接与解码状态，避免把正常直播批次间隔误判为断流。解析较大的 ID3 标签而等待网络数据时会让出 CPU。

普通音乐暂停保留当前缓冲与解码位置。网络电台暂停关闭连接，再次播放从实时直播开始。
断网时关闭连接并等待 Wi-Fi；音源暂时中断每隔 3 秒重试。音乐重连从头开始并重置播放时间，不声称无缝断点续播。
不支持的音源明确报错，不把缓冲/连接状态显示为已经发声。

`audio_device.c` 统一管理共享 ES8311/I2S 的所有权、格式与音量。
语音会话请求具有优先权，多媒体释放输出并暂停；会话/升级结束后由用户重新开始播放。
语音 Opus 编解码器和工作缓冲按会话申请、结束释放，不在待机期间占用播放资源。
暂停音源切换不会改写网络或显示偏好。

BSP 默认绘图/旋转缓冲约占 200 KiB 内部 RAM。本版通过项目内 `bsp_display_start_with_config()`
将这些缓冲移到 PSRAM，保留方向与软件旋转参数；TLS 数据缓冲也使用 PSRAM，硬件加密和 I2S 的 DMA 分配仍由驱动管理。
这项调整来自首次试播的 AES DMA 分配失败，诊断保存在 `build/flash-0.2.6-20260911/media-before-memory-fix.log`。

连续试播发现原海外音源吞吐不足：32.3 秒内只写出 12.5 秒 PCM。扩大 TCP 窗口与临时关闭未连接的 BLE 扫描都未消除卡顿，
电脑关闭本机代理后下载原音乐源的 512 KiB 也耗时 36.9 秒，说明不能用电脑经代理的可达性推定板端效果。
改用本地网络实测较快的默认音源后，同板 32.36 秒写出 32.39 秒 PCM，192 KiB 播放缓冲保持充足。
保留 57,600 字节接收窗口、按 1440 字节 MSS 配套的 42 个接收邮箱槽，lwIP 数据优先使用 PSRAM；这项预算调整不能解决音源本身的链路限速。
音频欠载时保留不完整的 MP3 帧，重新积累 8 KiB 后继续，并在界面明确显示缓冲状态。

## 验证和调试入口

主机检查调用生产 `media_model.c`：URL 边界、音源循环、MP3/ID3 头、任意分片位置的 ICY 元数据。
`media`、`wifi_networks`、`elm_protocol`、`ota_policy` 四项 C 测试通过。
同源界面检查覆盖六个主页、六种外观、新播放器及音源地址设置，共 8265 个标签无布局错误；
包含播放/暂停/停止、上一首/下一首、选台、拒绝提交、无效地址、保存与清除请求。
截图在 `build/ui-media-20260911`，其中播放状态是测试输入。

最终 0.2.6 已烧录到 COM28 的 P4 rev1.0，四个镜像摘要校验通过。实板音乐 32.313 秒输出 32.182 秒 PCM，
北京交通广播 13.422 秒输出 13.440 秒 PCM；补充的 18 项状态/控制检查全部通过，覆盖两个电台、两首音乐、暂停继续和停止。
测试结束保持停止，音量保留屏幕最后设置的 40。这里只验证解码与 I2S 成功写入，未人工确认扬声器听感。
完整过程与一次过早采样的暂停断言记录见 [P4 上板记录](P4_BRINGUP.md)；汇总在 `build/flash-0.2.6-20260911/media-final-verification.json`。

串口控制（返回 `ESP_OK` 表示命令已入队）：

```text
media open
media play 0
media toggle
media volume 35
media play 3
media stop
media url music "https://example.com/song.mp3"
media url radio "https://example.com/live.mp3"
status
```

索引 0/1 是音乐示例，2 是自定义音乐，3/4 是网络电台，5 是自定义电台。
`status` 提供状态、曲目索引、音量、成功写入的 PCM 帧数、播放时间与缓冲字节，不输出自定义 URL。
串口输入命令本身会回显 URL。板端验收、镜像摘要与限制记录在 [P4 上板记录](P4_BRINGUP.md)。
