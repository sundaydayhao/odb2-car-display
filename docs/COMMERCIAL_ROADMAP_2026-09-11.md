# P4 副屏商业化优化路线

评审日期：2026-09-11；代码基线：P4 v0.2.6、Android 采集 App v0.1.0。用户希望兼顾普通车主、改装车主、维修店与开发团队。

**结论**

已有可继续产品化的工程基础，目前属于功能样机阶段，适合在补齐供电与实车链路证据后进行限定范围试点，尚不足以支持面向普通消费者批量销售。缺口集中在核心数据价值、整机可靠性、用户独立使用、重复交付和付费证据。

本次评审读取当前源码、既有验证日志与产品文件，并核对官方替代产品资料。未新增实车、长期稳定性或客户付费验证，也未修改固件或烧录。旧的 [9 月 9 日评审](COMMERCIAL_REVIEW_2026-09-09.md) 保留为历史记录；关于配网、主题和媒体的旧缺口以本稿及当前 README 为准。

**兼顾三类客户的交付方式**

建议共用一套硬件、一份固件与数据模型，以三种使用模式提供不同的信息密度；这些模式是建议，尚未实现。先保留现有 P4+C6、7 寸触屏与外置 BLE ELM327 的方向。无需为了兼顾客户同时维护三个硬件版本。

| 模式 | 用户购买的结果 | 应交付的重点 | 当前边界 |
| --- | --- | --- | --- |
| 日常车主 | 上车即可查看所需车况，安装整洁，异常后能自行恢复 | 自动连接、点火/熄火行为、日夜可读、可靠提醒、便捷媒体和安装附件 | 界面、STA 扫描配网、媒体已具备基础；实际安装、休眠和长期体验未验收 |
| 进阶车况 | 获得目标车型原车不直观显示的数据，并理解变化 | 车型档案、已验证扩展参数、自选仪表、趋势、告警阈值与记录 | 当前只有最多 10 项标准 PID 映射，是否可读取仍取决于车辆；不能由协议连通推导油温、胎压、档位等都可用 |
| 采集诊断 | 把一次问题变成可导出、可复查的记录 | 限时采集、丢失标记、事件备注、筛选、回放/对比、报告与问题包 | Android 已有采集与导出实现，尚无真机/真车验收；无 DBC 解码和波形回放，手机 BLE 接收时间不是 CAN 硬件时间戳 |

采集模式在现有 ELM 入口下适合辅助记录和售后复现；不承诺全车总线无损、CAN FD、精确总线时序测量或任意车型协议解释。专业用户若以这些能力作为采购前提，当前套装不能兑现，不能仅通过增加菜单包装为专业分析仪。

软件模式、套餐和收费应由实际使用和报价反馈决定。首批可同时邀请三类用户，但每类只验证一个具体任务，不把每位试用者的全部定制要求都并入标准版。

**目前已得到的证据**

- STA 热点扫描、平板双栏设置、六种外观、蓝牙管理和多媒体已实现；4 项主机 C 测试及 8265 个同源标签/交互检查通过。预览不能替代实体屏幕光学和触控验收。
- v0.2.6 已在同一 P4 板烧录；实板音乐 32.313 秒输出 32.182 秒 PCM，电台 13.422 秒输出 13.440 秒 PCM，补充的 18 项控制检查通过。仅证明这些短时条件下的解码与 I2S 写入，未人工听音或验证长期音视频/车辆并发。
- 当前原型仍有 C6 主从版本提示、SD 初始化失败记录。未见当前版本的真实适配器/车辆数据对照、整车停车电流、生产云服务、断电 OTA 回滚或批量生产验收证据。
- Android 是开发签名侧载包，已有协议/离线分析测试；尚无真实手机权限、锁屏后台、真实适配器吞吐验收。
- 项目自有文件中未见可评审的量产原理图、PCB、结构图、完整 BOM、供应商报价或客户订单证据；不能据此判定硬件成本合理或利润成立。

证据入口：[P4 联调记录](P4_BRINGUP.md)、[多媒体](MEDIA.md)、[Android](../android-app/README.md)，以及 `build/flash-0.2.6-20260911/media-final-verification.json`。

**优化优先级与验收条件**

P0 是受控安装试点前的关键项；P1 是普通用户零售交付前应补齐的项。若首批承诺某项 P1 能力，则该项应前移。排序是本项目建议，不是认证标准。

| 优先级 | 当前缺口与影响 | 建议优化 | 应留下的验收证据 |
| --- | --- | --- | --- |
| P0 | 未验证真实车型与适配器；用户可能买到一屏不可用数据 | 建立车型/年款/动力/ECU 与适配器硬件/固件版本白名单，优先随附经验证的适配器；支持更换与重新绑定 | 每项宣称参数有来源、单位、参考值对照、更新间隔与失效行为；记录首次连接与重连时间 |
| P0 | 缺少完整上电、运行、熄火、休眠、唤醒策略 | 按实际供电路径设计状态机和电源保护；同时核查外置 OBD 适配器与车辆 ECU 的休眠 | 冷热启动、短断电、停车后的主机/适配器/整车附加电流实测；确认诊断轮询不妨碍目标车休眠 |
| P0 | C6 版本提示、SD 不可用，附加服务资源失败可能触发整机重启 | 固定兼容 P4/C6 版本；定位卡、供电、接线或驱动问题；附加服务失败时降级，维持核心车况显示 | 网络、媒体、摄像头、记录等故障注入；核心任务心跳、数据年龄、内存与队列峰值；明确故障恢复步骤 |
| P0 | 轮询周期可能超过部分参数有效期 | 按参数时限和实测响应安排采集预算，限制低优先级任务；不要靠放宽失效时间掩盖问题 | 在真实支持组合与媒体/联网负载下，记录每项数据的最大间隔、分位延迟、超时与失效率 |
| P0 | 告警是固定显示阈值，尚未形成车型策略 | 按车型配置阈值、持续时间、恢复阈值、优先级和事件记录；新增阈值先验证正常工况 | 冷车、怠速、正常高负载、边界抖动与数据过期时无错误警示；不以通用阈值宣称提前预测车辆故障 |
| P1 | 页面功能与可用数据不一致，首次使用仍有开发工具痕迹 | 按车型能力生成首页与可选项；未交付页面按模式收纳；增加首次使用向导、明确的错误恢复、设备解绑与恢复出厂 | 非开发人员独立安装、配网、绑定、选项设置和恢复；记录完成时间、失败点与求助次数 |
| P1 | 已能联网播放，但媒体长期维护和车内音频路径未完整 | 实测扬声器听感与车内噪声；根据客户车辆接口评估 AUX 等实际音频输出；提供电台目录、收藏、手机便捷配置、可更新的音源列表 | 热点关闭/恢复、弱网、无互联网、音源失效、语音抢占、音量与唤醒行为；与 BLE 车辆连接并发测试 |
| P1 | SD 默认满额停止，不能当作日常行程数据库；手机与副屏争用适配器 | 区分可循环日常记录和用户锁定的问题包，提供容量、导出、删除与一键问题包；明确手机采集/副屏恢复流程 | 存储满、断电、锁屏、系统杀进程、权限拒绝、适配器抢占及残缺文件恢复；采集丢失能明确解释 |
| P1 | 上传服务为本地联调工具，OTA 失败路径未验收 | 若承诺远程支持，补齐每台设备凭据、授权/解绑、版本与硬件匹配、灰度和撤回、有线恢复；首启健康检查覆盖采集任务 | 设备端断网/掉电/坏包/错板型/错签名/失败回滚；设备间数据隔离；P4/C6 兼容与恢复流程 |
| P1 | 开发板不代表量产整机，成本未知 | 完成电源、结构、支架、散热、线束、屏幕日照/夜间体验；形成 BOM、报价、产测工装、序列号与版本追溯 | 可重复装配/烧录/出厂测试；供货与替代料记录、良率、返修与支持工时；销售地区适用义务评估 |

以下源码问题当前仍存在：

- `main/app_main.c` 在启动车辆任务前，对语音、媒体、相机、云等服务启动使用 `ESP_ERROR_CHECK`；任务或队列资源申请失败可能导致整机重启。这不等于拔摄像头或缺 SD 必然重启，应按实际失败点做降级。
- `main/obd2.c` 每三次读取安排一次轮换辅助参数。全部 10 项均支持且每次响应平均为 r 时，8 项辅助值约每 `24 × (r + 50 ms)` 更新一次。r=150 ms 时约 4.8 秒，超过 `main/obd2_decode.c` 中部分字段的 4 秒有效期。该推导是源码分析，不是实车测量。
- `main/dashboard.c` 当前采用水温 105°C、油量 15%、转速 6000 rpm 等固定阈值；本次未证明这些阈值适用于目标车型。
- `main/recorder.c` 默认最多 16 文件、每约 60 秒或 256 KiB 封口，未确认上传的不覆盖。低速记录可能约 16 分钟占满文件数，达到大小上限时会更快；适合作为有界诊断缓冲，不能直接宣传全天行程历史。
- `tools/lab_server.py` 使用一个联调 bearer token；不能作为多客户生产数据隔离方案。当前配置未开启 Secure Boot、Flash/NVS 加密，应在量产威胁模型、密钥注入、维修和恢复流程中作明确选择，不能仅为补齐清单在原型上烧写 eFuse。

**市场比较与功能取舍**

官方资料显示，[Car Scanner](https://www.carscanner.info/) 已提供手机端实时车况、诊断和记录入口；[ScanGauge III](https://www.scangauge.com/products/productsscangauge-iii/) 提供车型扩展参数、行程与可配置告警。因此，独立副屏的购买理由应验证为持续可见、安装整洁、目标车型新增信息和可靠恢复，而非仅仅“能显示车速转速”。以上是官方功能说明，不代表市场份额或销量证据。

[OBDLink 官方支持说明](https://support.obdlink.com/support/solutions/articles/43000733076-troubleshoot-obdlink-issues-after-using-other-obd-apps) 明确提示同一适配器不能同时被多个 App 连接。这与当前副屏/手机采集的使用摩擦有关；交付时需要设计清晰的连接交接，不能让用户自行排查争用。

保留用户已要求的媒体、语音、摄像头与采集能力，但按模式和开关管理，不要求所有附加功能默认常开。C6 当前链路没有经典蓝牙 A2DP；联网 MP3 播放不能直接等同于手机蓝牙音乐或车机音频输出。新增 AAC/HLS、音乐平台登录、专业波形/DBC 等能力，先依据目标用户和来源兼容验证决定，避免同步扩展所有支持组合。

**量产、内容和数据交付**

按实际销售地区、无线模块/天线、整机供电和装车方式，向有资质的机构确认无线、电磁兼容和电气要求；不凭模块证书直接判定整机已符合全部要求。[工信部型号核准办事说明](https://ythzxfw.miit.gov.cn/bssx/axy/wxdhwxtx/art/2020/art_e00be70da40a4355afe7b869eba30fdb.html) 是国内无线要求的核对入口，本评审不判定具体认证适用性。

列出固件、字体、编解码库和内容来源的许可及维护责任；可播放的公共测试 URL 不等于已获得商品内容服务承诺。正式 App 需要发布签名、分发渠道适配、隐私说明、解绑/删除/导出和真实设备权限验收。云/语音收费与数据保存期限需写入成本及用户可理解的使用规则。

**收入与成本**

当前没有可靠 BOM、制造报价、支持工时或愿付价格，暂不承诺售价与毛利。先按统一税费/渠道口径记录：

`每台交付贡献 = 净收入 − 硬件/适配器/结构线材 − 装配产测包装物流 − 渠道费用 − 预期退换修与售后 − 对应云/内容服务成本`

研发、开模和工装等固定投入另列，不重复计入。普通版的低支持成本、进阶车型配置的维护工时、专业采集报告的服务工时分别核算；技术上共用不意味着可以免费无限适配车型。

**建议的下一轮验证**

1. 先冻结当前功能范围，补齐 P0；用已有开发板和临时结构做受控验证，得到供电、真实车况与故障恢复证据后再冻结量产 PCB/结构。
2. 以 1–2 个车型平台、1–2 个适配器版本起步。建议台架 100 次电源循环、24 小时组合负载观察，再做 7–14 天实际使用；这些是本轮计划样本与工程起点，不是认证标准、上市充分条件或工期承诺。连接时延和停车电流门槛需结合实测、安装方案及用户约定设定。
3. 普通车主验证“每天独立使用并愿意购买整套设备”；改装用户验证“至少一个真实有价值的新增字段/趋势”；维修或开发用户验证“导出的记录能帮助复现一次具体问题”。从车友群、改装/维修合作方获取候选人，本轮没有实际对外联系。
4. 分别记录实际使用天数、安装/求助时间、失败点、接受的完整报价与付费/采购反馈。只有演示好评时继续验证价值；关键数据不可得或支持成本超预算时缩小对应承诺；证据与交付贡献都成立后才扩大批次。

最优先的实施顺序：车型/适配器验证与电源状态机 → 数据时限/告警及故障降级 → 三种模式的首次使用路径 → 媒体与采集体验 → 生产维护与量产准备。
